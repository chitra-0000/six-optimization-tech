# SIX integration tests (H2)

Place `src/test/java/com/bnpp/regliss/six/it/` in the batch module's test sources (next to the existing ITs).
Re-add the project imports in IntelliJ (Alt+Enter / Optimize Imports): each file lists them in a TODO line.

## Run
- One class: run it from IntelliJ like the other `*IT` classes.
- All: `mvn test -Dtest='Six*FlowIT'` (or through your failsafe / IT profile if you have one).

## What runs
| Class | Scenarios |
|---|---|
| `SixImportFlowIT` | real XSLT + bulk write (rows per target, SIX_TARGET per regime); file waits at 90%; unreadable file -> nothing written |
| `SixDeliveryFlowIT` | complete delivery -> STRUCT confidence from INSTR, jobs 100% + ended, IN emptied, 1 filtered-export request per file; no SIX output list -> same but no request; other file not imported yet -> waits; file removed from IN -> whole delivery rolled back |
| `SixExportFlowIT` | filtering into FILTERED_SIX_*, poller rows READY, CONVERTER file built and released into DJ IN; only one file type filtered -> no file yet |
| `SixCleanupFlowIT` | older raw versions deleted / latest kept; delivery waiting -> raw part skipped; export finished -> filtered tables cleared |

12 tests. They passed (3 runs) on a local copy of the branch SIX classes with Spring Boot 2.7.18, Hibernate 5.6,
H2 1.4.200 (MODE=Oracle), Java 8 target. Reverting the "no SIX output list" fix makes the matching test fail.

## How it works
- `AbstractSixFlowIT` extends your `AbstractSpringBootTestBase`; `@InMemoryDb` (H2 profile) and a guard: the tests
  delete every SIX row, so they stop if the database URL is not H2.
- `hbm2ddl.auto=create` for this test context only; SIX schedulers switched off (`-` cron); IN / ERROR / IGNORE,
  DJ IN and holding folders in a temporary folder; data cleaned before and after each test.
- `SixH2Compatibility` (test only, H2 only): rewrites what H2 cannot run, no production change:
  - `generated as identity` (Hibernate Oracle12cDialect DDL) -> `generated by default as identity`
  - SIX_TARGET / FILTERED_SIX_TARGET foreign keys -> `on delete cascade` (as V2_469 / V2_470)
  - `FOR UPDATE SKIP LOCKED` -> `FOR UPDATE`
  - `TO_NUMBER(x DEFAULT NULL ON CONVERSION ERROR)` -> `SIX_IT_TO_NUMBER(x)`
  - `NEXTVAL FROM DUAL CONNECT BY LEVEL <= ?` -> `NEXTVAL FROM SYSTEM_RANGE(1, ?)`
  - `ALL_TAB_IDENTITY_COLS` lookup -> `INFORMATION_SCHEMA.COLUMNS`
  - `LOCK TABLE x IN EXCLUSIVE MODE NOWAIT` -> plain read
- A file is imported like `ImportService.doAutomaticSixImportFeed` (job, version, XSLT + write, imported file,
  SIX_CONFIDENCE_VALUES request, delivery check) without VersionService integrate/certify (not SIX).

## Not covered by H2
Two servers competing for the same rows (`SKIP LOCKED`) - needs Oracle (lower environment test).

## Project API assumed (check on first compile)
- `new ReglissList()` + `setName/ShortName/Reference/Active/Deleted`, `getImportConfiguration().setImportFileType(..)`
  and **`setAllowAutoUpload(true)`** (field `allowAutoUpload` is used by `findByDJFormatNotDeleted`)
- `new Version()` + `setVersionNumber(Long)`, `setImportFileType(..)`, `list.addVersion(version)` (as VersionService)
- `ImportedFile` setters as in `AdministrationFacadeLocalIT`, plus **`setOriginalFileName(..)`**
- **`new UnicodeBOMInputStream(InputStream)`**
- `SixCleanupService.Result` getters, `SixXmlGenerationPoller.generateXmlFiles()`, `BatchExportPoller.generateExportFiles()`,
  `SixBatchConfidencePoller.generateExportFiles()` (as in the branch)
- the SYS user can be found by `ReferenceService.getSysUser()` / `UserRepository.findByUsername("SYS")` in the H2 data
